## 3. Detailed Findings
### [CONCURRENCY]
#### Finding #1
Severity: `High`  
File: `src/Emcode.Pst.Libs/Infrastructure/Ndb/NdbBlockWriter.cs`  
Line: `93`  
Issue: Operasi `Seek` dan `Write` pada stream dilakukan tanpa lock di writer mutable.  
Technical Explanation: Posisi stream bersifat shared state; eksekusi paralel berpotensi menulis data/padding ke offset yang salah.  
Impact: Korupsi block PST dan inkonsistensi data tree.  
Risk If Ignored: Kerusakan data file yang sulit dipulihkan.  
Recommendation: Tambahkan sinkronisasi I/O di jalur write block.  
Suggested Refactor Code:
```csharp
private readonly object _ioSync = new();
lock (_ioSync)
{
    _stream.Seek((long)allocation.Ib, SeekOrigin.Begin);
    _stream.Write(buffer);
}
```

#### Finding #2
Severity: `High`  
File: `src/Emcode.Pst.Libs/Infrastructure/Ndb/PstNdbWriter.cs`  
Line: `69`  
Issue: State writer (`_tableRowCache`, `_existingBbt`, `_existingNbt`) dimutasi tanpa kontrak thread-safe.  
Technical Explanation: Koleksi mutable dipakai lintas operasi write sehingga race condition mungkin terjadi saat instance dipakai paralel.  
Impact: Snapshot BBT/NBT dan row cache bisa tidak konsisten.  
Risk If Ignored: Integritas PST menurun pada beban write concurrent.  
Recommendation: Tegaskan single-threaded contract atau tambahkan gate synchronization pada operasi publik.  
Suggested Refactor Code:
```csharp
private readonly SemaphoreSlim _gate = new(1, 1);
await _gate.WaitAsync(cancellationToken);
try { /* write critical section */ }
finally { _gate.Release(); }
```

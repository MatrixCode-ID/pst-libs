## 3. Detailed Findings
### Concurrency
#### Finding #`1`
Severity: `High`  
File: `src/Emcode.Pst.Libs/Infrastructure/Ndb/PstNdbWriter.cs`  
Line: `107, 171, 205`  
Issue: `Write path membuka FileStream dengan FileShare.Read.`  
Technical Explanation: `Writer membuka stream write menggunakan FileShare.Read, sehingga proses eksternal (mis. Outlook/indexer/antivirus) tetap dapat membaca file saat transaksi write berlangsung. Pada saat transaksi dimulai, NdbWriter menandai fAMapValid=false lebih dulu (lihat Finding #2), sehingga pembaca eksternal bisa melihat state sementara yang belum final.`  
Impact: `Dapat memicu error "corruption" atau read failure intermiten saat file diakses bersamaan.`  
Risk If Ignored: `Interoperability dengan Outlook tetap flaky pada workload real.`
Recommendation: `Untuk mode write eksklusif, gunakan share mode none atau mekanisme lock terpisah sampai commit selesai.`  
Suggested Refactor Code:
```csharp
_stream = new FileStream(path, FileMode.Open, FileAccess.ReadWrite, FileShare.None);
```

### Security
#### Finding #`2`
Severity: `High`  
File: `src/Emcode.Pst.Libs/Infrastructure/Ndb/NdbWriter.cs`  
Line: `310-315, 233-275`  
Issue: `Lifecycle fAMapValid menggunakan state invalid sementara tanpa proteksi eksklusif pembaca eksternal.`  
Technical Explanation: `EnsureAllocationTransactionStarted menulis fAMapValid=false sebelum rangkaian commit selesai, kemudian CommitBtrees baru mengembalikan menjadi true. Ini benar sebagai model recovery, tetapi menjadi risk tinggi bila file tetap readable oleh proses lain selama window tersebut.`  
Impact: `Pembaca strict bisa menolak file yang sedang dalam transisi commit.`  
Risk If Ignored: `Error buka PST di Outlook tetap mungkin terjadi walau struktur internal valid setelah commit selesai.`  
Recommendation: `Kombinasikan lifecycle fAMapValid dengan write-lock eksklusif dan optional temp-file + atomic replace untuk menghilangkan read-window transaksional.`

#### Finding #`3`
Severity: `Medium`  
File: `src/Emcode.Pst.Libs/Infrastructure/Ndb/PstNdbWriter.cs`  
Line: `352-360`  
Issue: `Dispose tidak memakai try/finally untuk jaminan penutupan stream saat commit gagal.`  
Technical Explanation: `Dispose memanggil CommitBtrees lalu baru _stream.Dispose(). Jika CommitBtrees melempar exception, baris dispose stream tidak dieksekusi. Ini dapat meninggalkan handle terbuka dan state file di tengah commit.`  
Impact: `Recovery dan retry menjadi tidak deterministic; potensi lock/partial-write meningkat.`  
Risk If Ignored: `Kegagalan commit sporadik bisa berujung file state tidak stabil.`  
Recommendation: `Gunakan pattern try/finally, selalu dispose stream, dan log state commit failure secara eksplisit.`

### Code Quality
#### Finding #`4`
Severity: `Medium`  
File: `src/Emcode.Pst.Libs/Infrastructure/Ndb/PstNdbWriter.cs`  
Line: `183-208`  
Issue: `EnsureFileInitializedAsync melakukan sync-over-async.`  
Technical Explanation: `Method async memanggil _bootstrapBuilder.BuildAsync(...).GetAwaiter().GetResult(), sehingga tetap blocking dan menghilangkan manfaat async, plus berpotensi deadlock pada host tertentu.`  
Impact: `Performa/skalabilitas menurun pada eksekusi paralel atau context sync tertentu.`  
Risk If Ignored: `Latency tinggi dan risiko blocking meningkat ketika dipakai dalam service async-heavy.`  
Recommendation: `Ubah method menjadi async penuh dengan await dan operasi stream async end-to-end.`

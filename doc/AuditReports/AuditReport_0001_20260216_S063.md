## 3. Detailed Findings

### CONCURRENCY
#### Finding #1
Severity: High  
File: src/Emcode.Pst.Libs/Infrastructure/Ndb/NdbBlockWriter.cs  
Line: 93  
Issue: Operasi `_stream.Seek` dan `_stream.Write` dilakukan tanpa sinkronisasi pada writer yang mutable.  
Technical Explanation: `Stream` position bersifat shared state. Jika method write dipanggil paralel, posisi stream bisa saling menimpa sehingga payload dan padding block tertulis ke offset yang salah.  
Impact: Korupsi block PST dan BBT/NBT inconsistency.  
Risk If Ignored: Data corruption yang sulit dipulihkan.  
Recommendation: Tambahkan lock khusus IO writer atau gunakan channel writer tunggal.  
Suggested Refactor Code:
```csharp
private readonly object _ioSync = new();
lock (_ioSync)
{
    _stream.Seek((long)allocation.Ib, SeekOrigin.Begin);
    _stream.Write(buffer);
}
```

#### Finding #2
Severity: High  
File: src/Emcode.Pst.Libs/Infrastructure/Ndb/PstNdbWriter.cs  
Line: 69  
Issue: State internal writer (`_tableRowCache`, `_existingBbt`, `_existingNbt`, `_ndbWriter`) dimutasi tanpa kontrak thread-safety.  
Technical Explanation: Dictionary/list mutable dipakai lintas method create/import/update table tanpa lock. Jika instance dipakai dari lebih dari satu thread, update NBT/BBT dan cache row-id dapat race.  
Impact: Snapshot btree/row cache dapat tidak konsisten.  
Risk If Ignored: Kerusakan struktur PST saat throughput write meningkat.  
Recommendation: Dokumentasikan single-threaded contract atau tambahkan synchronization boundary pada operasi public write.  
Suggested Refactor Code:
```csharp
private readonly SemaphoreSlim _gate = new(1,1);
await _gate.WaitAsync(cancellationToken);
try { /* mutasi writer state */ }
finally { _gate.Release(); }
```

### SECURITY
#### Finding #3
Severity: High  
File: src/Emcode.Pst.Libs/Infrastructure/PstEmlParser.cs  
Line: 27  
Issue: File `.eml` dibaca penuh ke memori (`ReadAllText` / `ReadToEndAsync`) tanpa limit ukuran.  
Technical Explanation: Input `.eml` yang sangat besar atau malformed multipart akan memicu alokasi string/array besar berulang (normalisasi line ending, split multipart, decode base64).  
Impact: Memory pressure dan potensi DoS pada service yang menerima file user.  
Risk If Ignored: OOM, latency spike, process recycle.  
Recommendation: Tambahkan batas ukuran file dan streaming parser untuk attachment/body.  
Suggested Refactor Code:
```csharp
var info = new FileInfo(emlPath);
if (info.Length > maxEmlBytes) throw new InvalidDataException("Ukuran .eml melebihi batas.");
```

#### Finding #4
Severity: Medium

Line: 66  
Issue: `ReadContentBytes` mengembalikan referensi `byte[]` internal langsung.

### CODE QUALITY
#### Finding #5
Severity: Medium  
File: src/Emcode.Pst.Libs/Infrastructure/Ndb/PstNdbWriter.cs  
Line: 1063  
Issue: `ParseNid` fallback ke `new Nid(0)` saat parse gagal.  
Technical Explanation: Invalid identifier tidak di-fail-fast, tetapi diam-diam diperlakukan sebagai root/zero NID.  
Impact: Operasi write dapat diarahkan ke parent salah.

Recommendation: Lempar exception validasi agar caller memperbaiki input.


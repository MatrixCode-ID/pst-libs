### Concurrency
#### Finding #`5`
Severity: `Medium`  
File: `src/Emcode.Pst.Libs/Infrastructure/Ndb/PstNdbWriter.cs`  
Line: `234-240, 275-282, 1290-1337`  
Issue: `Alokasi NID menggunakan cache lokal tanpa sinkronisasi counter HEADER.ROOT rgnid[nidType].`  
Technical Explanation: `NidAllocator menaikkan index dari snapshot NBT, tetapi tidak ada update ke header rgnid pada commit. Spesifikasi mewajibkan rgnid[nidType] increment saat create node sesuai type (doc/PST-241112.htm:29680-29689, 93046-93048).`  
Impact: `Counter header bisa drift dari kondisi NBT aktual.`  
Risk If Ignored: `Potensi collision/inkonsistensi pada operasi lanjutan atau recovery.`  
Recommendation: `Persist rgnid per NID_TYPE ke HEADER saat operasi create node selesai.`

### Security
#### Finding #`6`
Severity: `High`  
File: `src/Emcode.Pst.Libs/Infrastructure/Ndb/PstNdbWriter.cs`  
Line: `366-371`  
Issue: `Commit hanya menulis ulang BBT/NBT; tidak menjalankan lifecycle fAMapValid dan update metadata alokasi.`  
Technical Explanation: `Dispose -> CommitBtrees tanpa mekanisme set INVALID_AMAP sebelum write, update AMap/cbAMapFree/cbPMapFree, lalu restore valid state. Spesifikasi mengharuskan check/maintenance ini pada allocate/free/page create (doc/PST-241112.htm:91943-91955, 92169-92174, 92253-92263, 94282-94289).`  
Impact: `State integritas file rentan rusak pada interruption dan tidak sesuai recovery model PST.`  
Risk If Ignored: `Outlook repair/reject; potensi korupsi metadata alokasi.`  
Recommendation: `Implementasikan transaction-like write sequence untuk alokasi: invalidate -> mutate maps/header -> finalize CRC/trailer -> validate.`
